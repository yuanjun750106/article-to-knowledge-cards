# 用一条命令给日志表做分层归档

## 背景

`app.log` 按天追加，单文件到 500MB 左右时，检索会明显变慢，磁盘也开始吃紧。目标是把历史日志
压成归档，同时保留最近 7 天的原始文件以便排查问题。

## 步骤

1. 确认当天的写入进程已经切换到新文件。日志是按日期切分的，如果当天的文件仍在被写入，直接
   压缩会产生不完整的归档，所以先检查文件修改时间是否在最近 5 分钟内。

2. 找出 7 天以前、且已经不再变化的日志文件：

   ```bash
   find /var/log/app -name 'app.log.*' -type f -mtime +7
   ```

   `-mtime +7` 表示修改时间早于 7 个 24 小时之前。注意它按修改时间而不是文件名里的日期判断，
   所以补写历史文件的情况要靠第 1 步排除。

3. 用 gzip 压缩而不是直接删除，压缩后原文件会被替换为 `.gz`：

   ```bash
   find /var/log/app -name 'app.log.*' -type f -mtime +7 -exec gzip {} \;
   ```

4. 归档目录按月分桶，避免单个目录塞进上千个文件：

   ```bash
   find /var/log/app -name 'app.log.*.gz' -mtime +30 \
     -exec sh -c 'mkdir -p /archive/$(date -r "$1" +%Y-%m) && mv "$1" "/archive/$(date -r "$1" +%Y-%m)/"' _ {} \;
   ```

   这里用文件的修改时间决定归档月份，而不是执行时间，否则一次月底的批量归档会把整批文件都塞进
   同一个月份目录。

5. 最后删掉超过 365 天的归档。删除前先用 `-print` 跑一遍同样的条件确认输出，确认无误后再替换成
   `-delete`。

## 注意

- 这套流程只处理已经切分好的日志。如果应用把日志写在单个文件里，先解决切分问题，否则压缩会失败。
- `-mtime` 的行为受时区影响，跨时区部署的机器需要额外确认。
- 归档是可逆的：`gunzip` 能还原原文件，因此删除这一步是唯一不可逆的操作。
